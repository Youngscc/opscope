# 逐组合展示评估结果

2026-09-22。用户要求每个硬件×方法组合计算完成后立即显示，不等待整批完成。

## 实施设计

- 两个独立worker增加逐行JSON事件模式，stdout仅用于协议，计算日志仍写stderr。每个真实计算组合先报告running，完成后报告succeeded/failed；不支持的组合直接报告unsupported。保留原一次性JSON模式供已有脚本调用。
- 运行时预建queued组合，收到事件就更新该组合并发布带revision的部分payload；已完成结果不因后续失败而丢失。隔离进程超时后终止，只将未完成组合记失败。保持现有两个任务并发上限，不引入外部队列。
- 现有轮询接口可返回running状态下的payload。客户端每700ms检查增量版本；版本不变不重复发送大流水。每轮更新矩阵、图表及已打开详情，ID稳定，保留筛选/比较/页签。仅成功组合可比较；等待/运行/失败/不支持分别显示。
- 进度显示“已处理X/Y，已有N个预测”，X包括成功、失败、不支持。总数固定为请求笛卡尔积；未选组合保持not_run。图表统一刻度随新增结果重新计算，缺失不画零值。
- 修改配置仍取消旧请求，旧批次不能覆盖新配置。HTML快照只在整批完成后开放；中途JSON保留evaluation.status和计数，明确部分结果。离线客户端同步支持逐步更新。

## 验证计划

- 用同步屏障阻塞第二组合，确认第一组合在任务仍running时已可查询；验证首结果数值、等待状态、稳定ID和时间戳、最终计数。
- 验证单方法进程异常/超时保留已完成结果，未完成行置failed；JSON事件传输在进程退出前可读。
- 检查轮询revision省略未变payload、前端部分响应/旧响应隔离、无实测参考及null语义。
- 运行Python/Node测试、类型检查、生产与离线构建；桌面真实运行验证先Roofline后TileSim逐卡出现、详情/比较和导出。

## 验证结果

- 同步屏障测试确认第一个200μs结果已发布时，第二个仍queued且latency=null；最终第二个100μs结果可比较-50%，首结果ID/完成时间不变。
- 子进程只有父进程收到第一事件后才能退出的测试通过；超时后已收到事件保留，未完成组合失败；0值不丢失。
- API测试覆盖running payload、revision不变时省略payload、未完成快照409；离线客户端测试覆盖部分结果和旧配置响应隔离。
- 真实浏览器默认4096² FP16：16/40已处理时已有4个预测，TileSim仍等待；可打开H100 277.935μs详情。32/40时已有5个预测，单条JSON导出evaluation.status=running、total=40。最终7个预测，TileSim仍为390.891/627.736μs。无浏览器错误。
- 部分结果刷新以700ms轮询为基础；很快连续完成的组合可能在同次刷新显示，不人为逐卡延迟。模型初始化期间组合显示等待。

52项Python测试（含4项离线客户端检查）、2项前端状态测试、Vue类型检查/构建、离线生成与JS语法/diff格式通过。完成后HTML快照入口恢复，双TileSim对比仍为+60.6%。
