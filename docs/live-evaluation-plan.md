# 本地评估服务设计与实施计划

2026-09-22。基于 [复用分析](modeling-reuse-analysis.md)，用户已授权实施。仅改 OpScope，不修改上游或部署/推送。

## 范围与交互

保留紧凑白灰矩阵与蓝色主操作。硬件、方法、工作负载、预测、参考和缺失状态是界面核心；色彩沿用纸白、墨灰、交互蓝、Roofline蓝和TileSim紫。主要视觉特征仍是硬件×方法连续矩阵，不增加大面积统计卡片、装饰渐变或侧边导航。顶部配置按钮旁新增运行、结果快照，运行信息靠近操作。只验收桌面。

提供标准库本地HTTP服务，显式指定modeling目录与其Python解释器；不引入Web框架，不依赖数据库/身份系统。服务绑定127.0.0.1，提供同源页面与JSON接口。计算在隔离子进程执行，超时退出；请求不能提供路径、代码、任意算子公式或硬件规格。服务仅提供固定路由，限制请求大小、任务数量和同源写入。

GET /api/capabilities 返回服务与后端状态。POST /api/evaluations 接收configuration、hardware_ids、method_ids，返回任务ID；GET /api/evaluations/{id} 查询状态与结果；GET /api/evaluations/{id}/snapshot 下载可信后端生成的独立HTML快照。任务仅内存存储，服务重启即失效；前端保存最后完成结果供查看，配置变化使旧请求失效，不能覆盖新配置。

请求先按内置模板重建规范配置，再验证维度、dtype与张量契约。首批11基础模板及默认MatMul接入Roofline，未适配模板明示不支持。限定FP16/BF16/FP32及Embedding整数索引；不支持的执行选项拒绝，不静默忽略。保守限制输入规模，实际只建立TensorMeta，不分配设备张量。

每方法/硬件独立OpNode与RooflineSimulator，禁止自动方法回退与共享Hub缓存。TileSim依赖探测与方法入口独立；本阶段本体缺失时明确不可用，即使后来安装也需算子/硬件认证后启用，不自动冒充适配。Profiling无数据，方法3/4无后端。默认演示硬件仅明确别名映射到具体Server规格，R200示例仍未确认；选中的目录型号必须在白名单中。

结果契约opscope-evaluation-v1包含request_id、配置摘要、engine版本、工作负载、硬件规格摘要、实际方法、状态/原因、耗时和来源。synthetic=false表示实际调用模型，measurement=false、kind=analytic明确非实测。未执行/不支持/失败保持null，无参考不算偏差；各核活动为空。所有展示HTML由本地转义生成，不接受客户端HTML。双比较以同规范工作负载及同硬件或同方法为门禁；图表尺度按完整批次统一生成。

演示与评估整批切换，不保留混入的合成测量。配置应用后清空旧预测。离线index默认仍示例；运行需服务，结果快照内嵌配置与评估数据，file模式只读查看并允许回到示例。在线加载快照也不自动重跑。
