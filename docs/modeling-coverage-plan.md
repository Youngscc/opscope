# 补齐本地模型覆盖

## 目标与边界

补齐当前 FlashAttention 比较缺少的硬件配置、TileSim 输入转换和结果展示；保留既有 MatMul 工程流水及逐结果发布。来源为显式配置的外部引擎和其随包硬件资产，不改变外部仓库。预测不能标为设备实测。

## 计划

1. 接入已有 R200_Server Roofline 规格。910B1/B4 仅使用能追溯的完整规格；若原仓库没有，不伪造 HBM 或套用其他 SKU。
2. 对齐现有硬件到 TileSim 配置的映射；H100/B300 等借用 H200、Adevice03 借用 910B4 时，卡片和详情标出实际配置。
3. 验证新版 FlashAttention 输入接口，保留 B/N/S/D 与 dtype，明确理论/工程模式，不用 Roofline 替代失败的 TileSim。
4. 结果契约允许无流水的模型输出；只展示真实提供的耗时/分项/搬运信息，占位与缺失不冒充测量。
5. 执行数值、映射、形状和缺失语义测试，实跑当前 FA 配置及 batch/head 对照，验证在线详情和导出。

## 验证标准

成功表示该版本模型完成对应输入预测，不表示模型准确度验证。借用配置和模型本身的限制随结果导出；源仓库没有的参数保持缺失并记录原因。

## 实施结果与实跑（2026-09-22）

已实现 R200→R200_Server Roofline，TileSim 显式映射与三种结果路径，FA BNSD→引擎 B/N/S/D 输入转换，有/无流水详情和借用标记。保留原 MatMul DSL 工程路径。未修改 modeling 或安装包源码。

H100、B300 映射 H200，B200 映射 GB200；映射来源为原 backend 的 HW_INFO_MAPPING，不是独立 SKU 认证。GPU 配置的 BF16 cube/vector 参数确实未提供，不能偷偷以 FP16 替代。GB200/R200 的 FP16 理论 MatMul 实跑在 L0C→L2 带宽查找失败，已提前标为具体缺项；其 FA 工程模型还缺 UB/L0 参数。910B1/B4 没有完整 Roofline 规格，也没有可靠的整卡 HBM 聚合带宽映射，仍明确 unavailable。

56项 Python 测试（使用项目 Web 环境，无跳过）、4项离线交互和2项前端状态测试通过；Vue 类型检查/构建、离线生成和 diff 格式通过。浏览器当前 BF16 FA 的成功组合由5增加到9，核对浮窗分项、10624事件流水和JSON预览的输入、模式、模型假设；文件下载落盘未验证。单元测试覆盖无流水、占位null、借用比较、形状与逻辑数值；实跑成功仅为接口验证，没有真机精度认证。
