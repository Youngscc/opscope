# 结果矩阵与浮层详情设计

状态：已按用户授权实现矩阵、图表与浮层详情；下列设计中的验收范围见文末。日期：2026-09-21。

## 1. 使用目标与优先级

使用者是比较算子性能模型与硬件结果的工程师。一次查看聚焦一个确定的算子工作负载，先发现偏差，再查解释。

优先级：结果实用性 > 直观性 > 简洁性 > 装饰。美观来自稳定对齐、合理密度、克制的色彩和清楚的数字层级。

必须快速回答：

1. 同一硬件上，不同方法预测多少？与参考差多少？
2. 固定一种方法，不同硬件结果如何？
3. 哪些组合没有结果，为什么？
4. 选中的差异由什么输入、计时边界、计算/访存或执行行为解释？

不能把“预测更短”表达成“模型更好”；不能用方法平均耗时评价模型准确度；不能把不同定义的计数器画成统一指标。

## 2. 当前问题与设计取舍

当前每种硬件是一张多指标表，一屏难以同时看多硬件；左侧配置持续占宽；重复方法标题、微图和详情插入打断对齐。

调整为一张连续矩阵，固定行=硬件、列=方法，不再切换整页的分组结构。顶部配置摘要代替常驻侧栏，筛选收进有选中数量的弹出面板。矩阵是首要视觉中心，图表辅助比较，浮层解释细节。

矩阵不是独立大卡片的拼贴：共享方法表头、共享硬件行头、细分隔线，格子不重复硬件和方法名称，无逐格阴影。默认不显示二十四个“已完成”标签和“查看详情”按钮。点击数值区域打开详情，鼠标/键盘聚焦只给轻微背景反馈。

领域词汇：工作负载、硬件、评估方法、计时边界、参考偏差、算术强度、瓶颈、校准、执行依据。

视觉来源：实验台的纸白、金属浅灰、文字石墨色、选择指示蓝、参考青灰、异常琥珀。品牌强调色用于选择和动作；方法色仅用于图表标记与图例。不同方法的整列不用彩色大底。

识别性：坐标不变的硬件×方法矩阵，同格紧邻总耗时与参考偏差，Profiling基准列轻微底色，图表沿用矩阵行/列命名，详情沿用同一结果坐标。

避免三个常见模板：顶部一排无助于比较的KPI卡、每格塞多个仪表盘、三四张统计图同时争夺注意力。

## 3. 页面布局与密度

从上到下：

1. 精简品牌栏：OpScope、持续可见的“示例数据”。
2. 工作负载摘要：MatMul；M/N/K=4096；输入/输出FP16、累加FP32；设备侧单kernel。完整配置点击查看。
3. 单行工具栏：硬件筛选、方法筛选、显示指标、选择对比、导出。1366宽不足时工具栏分两行，不缩小文字。
4. 结果矩阵：默认展示当前六硬件×四方法；缺失组合保留。
5. 对比分析：一个图表区，可切换耗时/参考偏差。图表不压缩矩阵宽度。

1440px桌面设计：左右留白24–32px，硬件列160–180px，四方法列平分余宽；格子约240–270px宽、88–100px高，内边距12–16px。数字24px/600，辅助文字12–13px，表头13–14px。数字采用等宽数字字形并统一小数位。

1920px时内容最大宽1680px，避免标签和值横跨很远。1366×768至少能看到四行以上结果；1440×900目标看到完整六行矩阵或非常接近，不强求图表也挤在首屏。图表在矩阵下方是有意的优先级选择。

行列过多时固定行头/表头，矩阵容器支持必要的横向滚动；页面统一纵向滚动，不再套一个有独立纵向滚动条的矩阵。窄屏保留二维对应关系，允许矩阵横向滚动，不能拆成丢失列关系的瀑布卡片。

## 4. 单元格的信息层级

默认三层：

- 主数字：总耗时，如“157.00 μs”。
- 对照：如“较参考 −3.1%”；Profiling对应“参考”。
- 摘要：如“计算上界 · 已校准”。只有有依据的结论；回归仅有总耗时则“瓶颈未提供 · 已校准”。

示例：

```text
NVIDIA H100 × Roofline
157.00 μs
较参考 −3.1%
计算上界 · 已校准
```

上面的硬件×方法由行列标题表达，不在格内重复。默认不常驻计算时间、访存时间、带宽、缓存、活动率等，以免六行矩阵重新长成多屏。

显示指标首版仅“总耗时”和“参考偏差”：切到偏差后，偏差成为主数字，总耗时作为第二行；两者不会同时做大字。单位在数值旁，单位和格式全表统一。一个显示模式只有一个主指标。

不加入每格耗时条：行列已负责精确查询，下方图表负责长度/位置的直觉比较，避免重复编码和视觉噪声。可选偏差热力底色放到后续；若增加，必须对全表使用同一绝对偏差尺度，并另显符号方向，不能各行独立映射或把偏短标绿。

数据缺失用“—”与原因，格子仍可打开原因详情。当前示例不能标为真实任务完成。真实接入后再区分未运行/运行中/失败/不支持/支持待验证；不从available=false猜具体状态。R200保留“型号待确认”，不会自动转成支持。

## 5. 比较的含义

横向比较方法时关注与参考的偏差，纵向固定方法时比较硬件性能。行头、列头点击只聚焦图表，矩阵不重排、不消失；选中的行/列有淡背景和文字提示。图表标题直接写“Ascend 9382 · 比较方法”或“Roofline · 比较硬件”，用“返回全局”解除聚焦。

默认排序稳定，避免刷新后位置漂移；首版不同时提供多套排序和换轴。用户筛选时，图表范围随可见矩阵变化。没有结果的组合不自动隐藏，参考缺失则不算偏差。

一次查看一个明确工作负载。若以后同格包含多个历史任务，默认采用显式选定的run；尚未选定时提示“多条结果待选择”，不静默挑最快值或把不同运行平均成一格。

## 6. 图表设计

### 默认：参考偏差点图

矩阵已展示绝对耗时，默认分析图突出“预测哪里偏离”：纵向硬件、横向相对同硬件Profiling的偏差，0%参考线；低估在左、高估在右。距离0越近只表示本次总耗时更接近参考，不能推广成整体准确性。

每种方法用固定颜色和不同点形；多个方法在同硬件行内轻微纵向错开，不连成折线。当前三种建模方法最多十五个点，易于扫描；缺失不绘制为0。显示横轴单位%、左右“低估/高估”、清晰参考线和方法图例。没有合法参考时不显示此点并保留原因。全都无参考时默认改为耗时图并说明“暂无可用参考”。

### 耗时：横向分组条形图

统一从0开始的μs轴，硬件分组，方法为系列；方法颜色与偏差图一致。焦距为单硬件时仅四条，单方法时至多六条，数值直接标在条尾。全局视图保持分组，条数多时自然增高，不挤小标签。比例跨度非常大时允许显式对数刻度，首版不自动切换。

不画跨方法“最快预测”冠军，不计算混合方法的硬件排名。需要硬件快慢结论时，指定Profiling或单一评估方法，并确认工作负载和计时边界一致。

### 详情内：计算/访存并列条

只在单条或双条详情显示，省去全局一张重复图。分项时间不是百分比饼图或堆叠柱。活动区间可能重叠，解析成本也不一定包含全部固定开销；保留原始标签“活动/解析成本/未提供”，不能统一改叫“耗时占比”。

### 暂缓图表

雷达图暂不进入首版：当前没有三个以上独立、同定义且覆盖完整的评价指标；总耗时和FLOPs/总时延互相派生，放两个轴会重复计权，面积不能代表模型质量。

折线图用于后续seq_len、batch、矩阵规模等有序参数扫描；硬件型号和方法属于类别，不构成连续趋势。Roofline图待峰值/带宽与计算口径可验证后放在详情，目前硬件快照缺失不画假上界。禁止补回p50/p95、重复样本直方图。

## 7. 详情浮层

中心模态窗口；单条约1040px，双条约1280px，上限为视口宽减48px，高度上限约85vh。遮罩降低背景对比，不做重模糊。只滚动内容体，标题/关闭/页签固定。点击遮罩或Esc关闭，恢复原网格焦点、滚动位置、图表聚焦和筛选。

顶栏：硬件 / 方法；次行算子与数据来源；右侧导出、关闭。重要的口径不一致提示放在摘要附近，不藏在tooltip。总耗时旁同时显示参考偏差和依据状态。

五页签：

| 页签 | 信息 |
| --- | --- |
| 结果概览 | 总耗时、偏差、瓶颈、关键缺失；运行记录折叠 |
| 计算与访存 | FLOPs定义、逻辑字节/实际流量、分项成本/活动、带宽和缓存 |
| 执行过程 | 已有来源支持的核活动、流水、tiling；无来源显示原因 |
| 输入与硬件 | 输入输出tensor、dtype、计时边界、硬件快照 |
| 依据与数据 | 实际引擎、校准、回退、来源版本、JSON |

这里只重新分组现有八页签的信息，不删除张量表/任务上下文。标签和值紧邻，长文本另行，不用两端拉开的键值布局。

默认可点击整个数值区看详情。点击“选择对比”进入比较模式，格子出现复选框，最多选两条。选择与打开是独立动作；不会因为点复选框而打开详情。工具栏显示已选坐标与比较按钮，避免常驻底栏遮挡最后一行或图表。

双结果弹窗采用共享字段名、左右结果列的对齐比较，而非两个独立卡片各自排版；相同页签、同一纵向滚动。“仅看差异”只过滤标量表，图形各自保留，未知值不自动认作相同。一边无该字段时保留对齐位置和原因。

## 8. 可比性与可信度

计算比值前确认：算子/语义版本、全部输入输出shape/dtype、布局与关键属性、计时边界、结果单位、参考来源。比较不同方法时硬件快照一致；比较不同硬件时方法/引擎口径一致。允许查看不可比结果，但不生成偏差/加速比/优劣色，显示“口径不同”及具体字段。

例：任务127/128表面同输入，但输出契约和FLOPs统计不同；不能直接宣称推理比训练慢若干倍。这个提示应就在差值出现的位置。

unknown不等于相同，零值合法。参考为0时偏差未定义，原始0仍保留。缺少规格不能自动推算峰值利用率。图表读Python预处理结果，不在页面重新算性能/瓶颈；和数据库/导出保持同源。

当前为全局示例数据，参考也是合成参考；沿用全局synthetic及导出标记。校准只表示使用校准元数据，不等于已验证准确。硬件任务墙钟耗时与设备侧时延保持分开。

## 9. 验收标准（待实施）

- 1440×900下默认四方法完整可见；六行能整体扫读，行列对齐，数字不跳位。
- 不点详情可读总耗时、参考偏差、瓶颈/缺失；点击一次打开浮层，背景矩阵位置不变。
- 行/列聚焦更新图表并保留上下文；缺失与零值在矩阵、图表、导出一致。
- 同样数据切显示指标不能改变计算结果；矩阵、图表、详情的值与单位一致。
- Profiling参考缺失/为0、H200回归分项缺失、R200型号待确认和未验证支持都有准确状态。
- 两结果不满足比较条件时仍可看原始数据，但无误导比值或排名。
- 键盘可用：原生按钮和复选框、可见focus、对话框焦点约束、Esc退出/焦点返回；颜色之外还有文字/点形。
- 100%及200%缩放可读；关闭浮层不丢筛选/选择/位置；不把临时手机视口留在用户页面。

## 10. 实施顺序（已完成首版）

1. 确认当前设计，先整理展示字段与可比性规则，保持示例数据边界。
2. 在现有原生HTML/CSS/JS与Python生成器上替换主矩阵；保留原有详情内容与导出。
3. 接入原生dialog、统一单条/双条详情和焦点恢复。
4. 加入偏差/耗时图表；数值、比例、格式与图宽由Python预处理，JS负责选择与渲染。
5. 更新架构及语义文档，补具体数值/缺失/交互检查，构建并在桌面核验。

首版沿用原生HTML/CSS/JS与Python标准库，未引入新依赖。实施计划见 [计划](result-matrix-plan.md)。

## 11. 实际交付与验证

已实现：六×四矩阵与空格原因、顶部硬件/方法筛选、总耗时/偏差主指标、偏差点图/耗时条形图、行列聚焦、可点击图表标记、五页签原生浮层、两结果共享字段对齐、仅看差异、任务记录折叠、JSON原有导出。相对差值与图表坐标由Python生成。

已验证18项数据单测、JS语法、构建一致性；浏览器1440×900/1366×768及375×812布局，筛选和空结果、单条/双条详情、缺失硬件规格、H200回归分项缺失、Esc焦点返回、箭头页签、单条1/双条2/筛选H100四条JSON且无展示HTML。JSON下载链接内容已解析核对，下载落盘未验收；200%浏览器缩放、屏幕阅读器及完整可访问性审计未验收。

实现取舍：当前仅合成fixture契约；真实来源未校验时保守禁止比值，不具备真实数据接入能力。桌面采用固定表头，窄屏采用固定行头及矩阵容器横向滚动。暂不做对数刻度、雷达图与性能阈值评分。
