# 结果矩阵实施计划

2026-09-21 用户已授权按 [设计文档](result-matrix-design.md) 实施。

## 设计决定

使用 interface-design 的信息层级/领域探索，以及 UI UX Pro Max 检索到的 Data-Dense Dashboard、Focus States 与 Focus Not Obscured 建议。首次 design-system 的拟物/营销页推荐与用途不符，已弃用；采用明确领域重检的紧凑数据表建议，不引入库或远程字体。

意图：工程师先扫读硬件×方法结果，再查看偏差原因。矩阵数字为焦点，配置摘要次之，分析图位于矩阵之后。视觉来自实验台：纸白表面、金属浅灰底、石墨文字、蓝色选择、青灰参考、琥珀提醒。圆角8–12px，矩阵细边线；浮层单独使用柔和阴影。文字14px基准，数据24px/600、标签12px/500，4px间距基准，格内16px。原生控件和dialog负责可访问交互。

## 实施步骤

1. 增加 Python 矩阵展示预处理：统一动态图尺度、每条结果坐标、详情分组与成对可比性说明。保留原结果与合成数据语义。
2. 重写页面骨架和主交互：全量六×四矩阵、顶部筛选、主指标切换、行列聚焦、选择比较。
3. 原生dialog呈现单/双详情，五个页签，标量逐项对齐、只看差异；保持输入输出、硬件缺失和执行细节。
4. 绘制偏差点图与耗时条形图，刻度由Python统一生成，JS只筛选和呈现；图标/标记原生SVG或CSS，无新增依赖。
5. 更新测试与架构/记忆，生成index.html；验证Python数值/状态、JS语法、桌面/窄屏、筛选、图表、弹窗、比较与导出。

## 边界

- 当前只有一组MatMul合成工作负载；模拟方法的结果并非实际运行。
- 同硬件同工作负载的合成参考可展示示例偏差；缺硬件快照明确标示，不能外推到真实数据可信度。
- 跨硬件又跨方法的双比较可看字段，但不生成加速比；真实数据无完整契约时保守拒绝比值。
- 不新增雷达图、无序折线图、样本分布或p50/p95；不修改modeling；不提交、推送或部署。
