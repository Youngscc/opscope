# 单算子任务详情完善

## 设计

沿用现有界面，不另建视觉版本。参考 modeling 前端 PerformanceOpPage 的耗时、硬件规格、Tensor Footprint、Bound 分析，以及 TaskHistoryPage 的配置快照和运行信息。推理 E2eOperatorPerf 的依据展示用于区分公式与实际来源。

新增任务概览、输入输出、硬件配置三个页签；已有耗时、计算、访存、各核与流水、执行依据保留。查看详情与双结果比较默认进入任务概览；外层指标快捷入口仍直达对应页签。当前详情 JSON 仅导出已打开的一或两条结果，全局导出仍是筛选范围。

单条结果新增 task、workload、hardware_snapshot 结构，由 Python 生成展示 HTML 和数值。任务 ID/run ID/状态时间/实际后端/回退/报告/峰值规格无真实来源时保留 null；task.status=demo 不代表执行成功。同硬件跨方法的 workload_id 相同，结果 ID 独立。缺失组合仍无耗时、不提供详情入口。

输入 A/B 和输出 C 均为 [4096,4096] FP16、每个 33554432 bytes；输入共 67108864、输出 33554432、逻辑合计 100663296 bytes。布局 row-major、不转置、FP32 累加沿用现有工作负载。张量占用不是峰值显存或实际 HBM 流量。

硬件配置仅使用目录已有名称、家族、说明；显存、HBM 峰值、L2 容量、FP16 峰值、核数为 null。已有虚构时钟、Tiling 保留在执行依据，不伪装提交时的硬件快照。无硬件峰值不画 Roofline 转折点或利用率滑块。校准仍是一个 Roofline 方法的元数据。

## 计划

1. 新增 task_details.py 统一构造结构化上下文与三个页签内容。
2. build.py 将上下文加入每条结果；app.js 和 shell.html 接入页签、详情导出。
3. 扩展原版 CSS 的紧凑标签/数值、张量表和双列布局。
4. 精确测试字节数、方法与实际后端分离、缺失语义、回归不伪造分项；构建、语法检查，浏览器检查单条/双条详情、筛选、JSON。

## 来源边界

参考的是本机 modeling 前端源码布局与字段，不读取用户任务数据库，不复制历史任务或凭据。PerformanceOpPage 的 TileSim 分支存在 runTilesimFake，仅为展示入口，不能据其成功状态声称已执行仿真。本次不接入 modeling API、不新增模拟器执行或重跑功能。
