# 两次评估对比

## 目标与边界

在线页面可选服务当前保留的两次评估时间，比较同一硬件×方法组合的结果。服务只在内存中保留最近 12 个任务，重启后历史消失；这不是持久实验档案。离线 HTML 没有历史任务服务，因此保留原有单批结果比较。

## 数据流

`GET /api/opscope/evaluations/history` 返回终态任务的 ID、提交时间、完成时间、算子、配置摘要和成功数，不返回完整 trace。`GET /api/opscope/evaluations/compare?left=…&right=…` 从两份既有快照按硬件与方法配对，并在 Python 中计算可比性、总耗时变化、统一图宽和汇总计数。前端只负责选择时间、切换组合、绘图和详情呈现。

同一组合必须两侧均成功、有相同配置摘要、硬件规格摘要和引擎身份，才计算耗时变化率。任一缺失或身份变化时保留 A/B 原值及原因，不计算比率。A 耗时为零时保留原值，变化率未定义。统计只数可比组合，不把不同硬件/方法的耗时加总成一个平均性能指标。图表为每个可比组合的两根同尺度总耗时条，精确值及变化率始终显示在旁边；其他各项输出按章节并排展示，原始结果可展开查看。所有值为模型预测，非设备实测。

## 验收

- 新完成评估后可选两个不同时间；刷新页面仍可选择服务内尚未淘汰的任务。
- 同口径两次结果有逐组合图表、变化率及更短/更长/相同计数；不同口径和失败结果并排但无变化率。
- 详情覆盖两侧已有的概览、耗时、计算、访存、输入、硬件、依据及执行字段；缺失不变成零。
- 无历史、仅一次、任务被淘汰或服务重启时给出明确状态；原矩阵与单批双结果比较不受影响。
